# G08｜工作流注册与渲染计划编译

> 状态：DRAFT_FOR_REVIEW。交付阶段：B2。前置：G02、G06、G07；G10 提供契约验证环境。下游：G03、G09、G10、G12。

## 1. 目标与边界

将创作镜头转换为确定的生成输入。用户和 Agent 描述目标与参考素材，编译器选择经过测试的模型工作流、验证能力并固定参数。ComfyUI 节点编号、Python 实现和模型文件路径仅存在于工作流包和适配器内部。

## 3. WorkflowBundle 合同

包包含 bundle_id/version/digest、API Format graph、公开参数 Schema、参数到节点输入的 bindings、required_models 的文件摘要、custom_nodes 的源码提交/包版本、Python/框架依赖锁、容器镜像或环境制品摘要、输入输出节点清单、能力 profile、预估资源/超时基线、契约测试样例与报告引用。

能力 profile 明确：t2v/i2v/首尾帧/角色参考支持情况；允许宽高集合或步长约束；允许帧数及其计算规则；原生 fps；镜头最大持续时间；必要参考图数量；参考图裁切规则；是否输出音轨；已知限制。`character_reference` 标签必须对应实际节点和有效测试，不能只是 Worker 自报字符串。

公开参数是稳定字段，例如 positive_prompt、input_image、seed。bindings 映射到固定节点路径。注册时校验目标节点存在、输入类型匹配、必要输出可收集；图发生变化必须生成新摘要。

## 4. 编译过程

1. 加载 ShotRevision、TimelineRevision、ReferenceSetRevision 及目标 ProductProfile，核对摘要和审批状态。
2. 根据明确策略和用户选择挑选兼容 Bundle；没有兼容工作流就返回具体能力缺口，不用“最接近”的不兼容模型偷偷执行。
3. 模型特定提示词编译可以使用模板或受控 LLM。若使用 LLM，作为独立 CreativeTask 保存结果并计费；重新运行可能不同，因此结果必须先落库后作为 RenderSpec 输入，不能在每次 GPU 重试中重新生成提示词。
4. 固定种子、原生尺寸/帧数/采样参数和全部参考文件摘要；输出完整 resolved_inputs。负向提示词只有在 Bundle 支持时写入。
5. 校验原生生成长度足以覆盖需要的画面；允许按明确计划裁尾、缩放或补独立静帧，任何影响表达的裁切/变速先要求确认。
6. 写 RenderSpec、输入依赖边和 execution_digest，组装 RenderPlan；G03 以该计划冻结 ProductionSnapshot。

RenderPlan 包含 slot_id、candidate_id、render_spec_ref、required_capabilities、dependency_refs、expected_outputs、postprocess_plan、estimated_gpu_seconds/cost、estimate_profile_version。candidate_id 在用户要求新增候选时重新产生；重试编译/冻结同一命令不得重复增加候选槽。

## 5. 镜头依赖与并行

独立镜头可以同时调度；若镜头 B 必须使用 A 的最后一帧，就在计划中声明 `A.artifact.last_frame → B.reference`。B 的最终 RenderSpec 只能在 A 的实际产物确认后完成，属于分阶段计划；冻结快照保存该依赖和编译规则，解析出的 RenderSpec 作为不可变执行派生记录，不修改原快照。

依赖图必须无环；任何动态解析都记录具体输入摘要和编译器版本。A 重做后，G12 识别 B 的衔接依赖失效。不能一边要求跨镜头首尾衔接，一边把所有镜头无条件并行。

## 6. 包验证与执行兼容

在隔离验证节点进行 schema/节点/模型检查、最小样例生成、输出可解码检查、取消/错误行为测试，之后才将 Bundle 标成 ENABLED。首次真实运行前固定所有依赖，不把自定义节点锁定延后到规模化阶段。

Worker 注册时报告已安装的闭包摘要；调度匹配能力和摘要，执行前再次校验，防止注册后文件被替换。模型名一致但 SHA-256 不同视为不同环境。容器摘要不能单独证明外部挂载模型正确，必须检查挂载模型摘要。

Bundle 停用后禁止新制作采用，已有快照可以按策略继续固定版本；发现严重缺陷时显式暂停受影响任务。升级回退切换的是包选择规则，不原地覆盖旧包。

ComfyUI 的 `/prompt` 接受执行图入队，`/object_info` 提供节点描述；它们帮助进行模板验证，业务侧仍需维护版本与能力合同。[ComfyUI 路由说明](https://docs.comfy.org/development/comfyui-server/comms_routes)

## 7. 失败与实现任务

缺模型/节点、参数不兼容属于配置失败，不能通过同输入重复计算解决。OOM 可交给 G09 选择更合适但兼容的 Worker；如果需要降低分辨率、精度或换模型，创建可审核的新执行计划，不冒充原任务重试。

实现任务：Bundle Manifest/验证器 → 单套 i2v 模板注册 → PromptCompiler → 参数注入/解析器 → 依赖计划 → 资源基线测量 → 升级对比与固定版本测试。首版手工维护一套模板即可，不要求先做可视化节点编辑器。

## 8. 验收条件

- G08-A1：同一冻结输入与编译结果生成相同 execution_digest；Node 编号变化只能通过新 Bundle 接入。
- G08-A2：能力不支持负向提示词/尺寸/帧数时提前报字段级错误，没有 GPU 提交。
- G08-A3：外部挂载模型文件被替换后 Worker 准入失败，即使文件名和镜像未变化。
- G08-A4：B 依赖 A 末帧时，A 未完成不能提交 B；重做 A 后 B 的旧结果被正确标为依赖过期。
- G08-A5：Bundle 升级后旧制作快照仍引用旧摘要，新制作使用新摘要，双方结果可区分。
- G08-A6：受控 LLM 提示词编译只在生成新执行输入时运行，GPU 技术重试不重新调用它。

## 9. 供审核的取舍

首版限制可用工作流数量，优先完成稳定注册、参数映射与验证。Agent 可以推荐工作流类别，但实际能力准入、模型选择和参数合法性由程序判定。升级效果以同组样例的人工和技术检查证明。
