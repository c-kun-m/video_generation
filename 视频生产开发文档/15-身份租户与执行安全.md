# G15｜身份、租户与执行安全

> 状态：DRAFT_FOR_REVIEW。交付阶段：B0 单用户身份/所有权/执行边界，B4 多用户完整验收。前置：G00、G01；与 G02/G03 共同实现基础。约束：全部模块。

## 1. 目标与边界

从第一版建立明确的用户、工作空间、数据所有者和执行权限。首版即使只有一个用户，也不能默认所有请求可信；多用户开放前验证项目、素材、命令、事件、缓存和 Worker 通道的隔离。这里的保护针对本产品实际上传/模型/后台执行能力，不额外引入与业务无关的审批系统。

## 3. 身份和部署形态

本机 Alpha：服务仅监听 loopback，首次管理启动创建唯一 owner 身份；桌面经一次性配对建立设备会话，认证秘密由 Main/Bridge 的受控存储管理。不能把“来自 localhost”当作唯一认证，其他本机进程也可能请求该端口。

多用户/远程 Video Service：使用受控 TLS 入口及经验证的账号/OIDC 会话方案；请求校验会话、CSRF/Origin（若采用 Cookie）及速率限制。具体身份供应商在部署基线确定，业务层只消费 ActorContext，不把供应商 token 散布到模块中。

Worker 使用独立服务身份、注册授权和短期任务访问令牌，不复用用户登录秘密。服务凭据只允许调用 internal worker 端点，不能修改用户审批和预算。内部端点不因为有 `/internal` 前缀就免认证。

## 4. 权限合同

`ActorContext` 包含 actor_id、actor_kind、tenant_id、membership_version、capabilities、session_id。接口体中的 tenant_id 若存在必须拒绝冲突；数据库仓储始终显式接受已验证的 TenantScope。

| 角色 | 可做 | 不自动拥有 |
|---|---|---|
| owner | 成员管理、项目配置、预算策略、编辑和审批 | 任意服务器 Shell/未经验证工作流执行 |
| editor | 创建/编辑内容、提交制作、在额度内请求候选 | 修改成员/额度、替别人批准 |
| reviewer | 查看授权项目、审片和批准对应版本 | 编辑原始内容、增加生成费用 |
| viewer | 查看授权项目与已允许的素材/导出 | 写操作和后台执行 |
| operator | 查看运行诊断、暂停节点、按授权执行恢复 | 默认读取全部用户素材/修改创作内容 |

单用户 Alpha 的 owner 可兼任 editor/reviewer，基础判断函数不写死 `allowAll`。复杂“必须不同人审批”策略属于后续，可通过 policy_version 扩展。

资源授权覆盖对象本体与派生信息：Project、Revision、Command、Event、Artifact、Lineage、Export、缩略图、签名下载、缓存和错误文本。猜中 ID 也不能越权读取。SQL 复合外键和 TenantScope 查询为基础，多用户版本可加 PostgreSQL RLS 作为第二层；不能用 RLS 替代 API 角色判断。

## 5. 执行与输入边界

ComfyUI 自定义节点会执行代码，因此只有管理员可登记/启用固定摘要的 Bundle。普通用户不能上传任意 workflow JSON 让后台执行，也不能要求 Agent 修改节点安装脚本。节点运行使用受限服务账号，文件挂载与网络访问限制在模型/工作目录及必要供应商范围。

上传参考素材视为不可信内容；先验证类型、大小和解码，禁止外部 URL 自动抓取作为默认上传方式。以后支持 URL 导入时，要经过服务端出站目标检查和重定向检查，不能访问元数据/内网管理接口。

模型输出和素材内文字只作为创作数据，不作为系统指令。Agent 不能调用任意系统 Shell 或绕过预算/审批；FFmpeg 使用参数数组和固定模板。工作流输出文件路径必须经 G10 根目录校验。

## 6. 凭据、审计与撤销

LLM/TTS 密钥、对象存储秘密、数据库口令、Worker 凭据不进入 Renderer 状态、队列载荷、Temporal 历史、普通日志和诊断包。用户输入新密钥只在专用受控提交过程中短暂存在，不提供明文读回接口。

审计记录包括 actor、动作、目标版本、结果、command_id、trace_id、policy_version 和必要理由。重点动作是审批/撤销、预算调整、Bundle 启用/停用、未知结果人工认领/重做、节点隔离和删除素材；日志不复制整段敏感素材或秘密。

撤销会话后阻止新命令和媒体授权续签；正在播放的短期读取允许最多持续到授权有效期上限，必要时主动断开。移除成员后旧缓存由桌面清理，后台每次领取/最终登记仍检查相关任务授权策略。对已运行任务是否取消由项目策略明确决定并记录，不能把成员移除等同于 GPU 已立即停止。

## 7. 实现任务与失败处理

B0 建立 owner/设备配对、ActorContext、TenantScope 和 Worker 身份；B1 起所有 API 和素材访问接入同一授权函数；B4 完成多角色、多租户及撤销测试。认证系统故障时写操作拒绝，已授权执行的收集可通过仍有效的服务身份完成，不能因此丢弃已生成产物。

测试数据至少有两个租户、每租户多个项目，以及 owner/editor/reviewer/viewer/operator。跨租户资源不存在与不可访问返回一致的公开错误，内部保留诊断证据。

## 8. 验收条件

- G15-A1：未认证本机请求、伪造 tenant_id、Worker 身份调用审批接口均被拒。
- G15-A2：租户 A 无法读取 B 的项目、事件、命令结果、素材、缩略图、血缘或导出，即使知道 ID。
- G15-A3：reviewer 可批准具体版本但不能请求新生成；editor 无法修改预算上限。
- G15-A4：上传伪装文件、目录逃逸、任意 URL、恶意字幕和任意 workflow 图无法绕过执行边界。
- G15-A5：凭据扫描在日志、Temporal 载荷、诊断包、Renderer 存储中没有发现测试秘密。
- G15-A6：会话/Worker 凭据撤销后不能继续新提交，已有任务按明确策略收敛且有审计。

## 9. 供审核的取舍

单用户版本先具备所有权与最小授权，暂不交付复杂企业组织和双人审批。多用户开放是一项独立发布门槛，不能仅增加 users 表就宣称隔离完成。
