# G12｜依赖失效与局部重做

> 状态：DRAFT_FOR_REVIEW。交付阶段：B3。前置：G02、G03、G06–G11。下游：G04、G13、G14。

## 1. 目标与边界

用户修改项目后，系统能解释哪些步骤需要重做、哪些产物可继续使用，并在用户确认后创建新版本和制作批次。依赖判断基于实际输入，不以“项目版本变了”作为重跑整片的理由，也不只靠镜头编号猜测可复用性。

## 3. 依赖数据与规则

依赖边方向为“产物/对象依赖输入”。例如 RenderSpec 依赖 ShotRevision、角色参考图片、编译提示词和 Bundle；Artifact 依赖 RenderSpec/实际执行环境；字幕依赖文本/对齐；CompositionRevision 依赖选片、音轨、字幕、时间线与输出 profile。

每条边包含 role，例如 visual_identity、spoken_text、subtitle_display、timing、last_frame、render_parameters、output_format。字段修改映射到角色类别，再沿反向边寻找依赖项。保存版本完整内容保证可追踪；字段级比较和派生摘要决定是否真正影响执行。

| 修改 | 首次直接失效 | 继续传播 |
|---|---|---|
| 项目标题 | 项目显示/导出说明 | 不影响镜头和配音 |
| 仅字幕显示错字 | SubtitleRevision | 合成、成片审批、导出 |
| 旁白朗读内容/声线 | VoiceAsset、Alignment | 字幕、时间线复核；时长/画面需求变化再影响相关镜头 |
| 镜头动作/构图 | 该 ShotRevision 对应 RenderSpec/候选 | 依赖其末帧的后续镜头、选片和合成 |
| 角色参考图片 | 引用该图片摘要的 RenderSpec | 对应镜头及其连续性依赖 |
| 背景音乐 | 混音/CompositionRevision | 成片审批和导出 |
| 全局风格 | 引用该风格的镜头输入 | 可能全部镜头，必须如实显示 |

未知/未声明依赖默认标 NEEDS_REVIEW，不自动复用。新工作流引入新的输入字段时，必须同时更新依赖提取器及固定测试样例。

## 4. ImpactPlan 合同与算法

`ImpactPlan` 包含 impact_plan_id、project_id、base_snapshot_ref、base_heads/row_versions、change_digest、dependency_graph_version、changed_refs、invalidated_outputs、revalidate_outputs、reusable_artifacts、new_tasks、cost_estimate、estimate_version、expires_at。

算法：规范化拟修改内容 → 校验合法性与基准版本 → 计算字段/摘要差异 → 拓扑遍历反向依赖 → 区分必重做与仅需验证 → 查询可复用 Artifact → 检查 READY/权限/保留/输入兼容 → 生成任务差异和成本说明。

对真实执行输入、编译器/环境摘要相同的产物，可以跨 ProductionRun 复用。复用保存 Artifact 直接引用和新的依赖关系，不复制成一个假的“新生成”记录，也不新增 GPU 结算。变化了 QC 规则时只重新质检，除非质检结果要求重生成。

Plan 默认有效 10 分钟；即使未过期，提交时仍比较所有相关头版本、候选选择、工作流启用状态及素材有效性，防止“计划计算后其他人又修改了项目”。价格变化超出已确认上限时重新预览。

## 5. 提交与执行交互

用户确认影响与费用 → G03 校验原 command_id 和 ImpactPlan → 在事务中写新内容版本、快照和新 Run、复用引用与 Outbox → G04 只为 new_tasks 调用 G09 → 未受影响 Artifact 直接进入待选/复用结果 → G11 验证选片 → G13 生成新成片。

旧 Run 不因新 Run 创建自动被取消。界面可以同时提供“保留旧批次继续完成”和“取消旧批次”的明确操作；取消走 G04/G10 的真实停止流程。首版每项目只显示一个当前编辑分支，但历史制作批次始终可查看。

用户主动“再生成一个”时创建新 candidate_id/job_id；可复用输入素材、已编译提示词和模型缓存，但不能把旧生成视频当作新候选返回。需要改变种子时创建新的 RenderSpec；保留种子时仍是新的有明确成本的操作，系统不保证生成画面必然不同。

## 6. 失败处理与实现任务

提交计划与当前版本不一致返回 IMPACT_PLAN_STALE，并展示新增变化；不能后台自行扩大用户已同意的重做范围。复用素材已被删除/隔离时重新计算计划，禁止到合成阶段才发现引用断裂。

旧版本结果晚到保存到其原 Run；可以提示用户有新的历史候选，但不得覆盖当前 content_head、selection_head 或新成片。人工保留某个已过期镜头时，需要产生可追踪的创作取舍和新的兼容快照。

实现任务：依赖提取器 → 图验证/失效算法 → 复用规则 → ImpactPlan API → 原子提交 → 差异展示 DTO → 字段级修改与晚结果测试。算法可以使用数据库边表和内存有向图，首版不需要另建图数据库。

## 7. 验收条件

- G12-A1：只改字幕显示文本，新 Run 不创建 RenderJob，不重新调用 TTS，只产生必要合成任务。
- G12-A2：改镜头 3，镜头 1/2 的 Artifact 被直接引用；依赖镜头 3 末帧的镜头 4 被标需重做。
- G12-A3：改角色参考只影响实际引用该素材的镜头，不漏掉间接依赖。
- G12-A4：项目标题修改不改变执行摘要，不要求重生成；全局风格变化如实列出全部受影响镜头。
- G12-A5：预览后另一客户端修改内容，提交原计划返回过期冲突，没有偷偷扩大的生成费用。
- G12-A6：同参数主动再生成得到新 Job；重发原命令仍只有一个新 Job。
- G12-A7：旧 Run 的结果晚到不能覆盖当前选片，历史结果仍可审查。

## 8. 供审核的取舍

选择“先显示影响，再执行重做”，增加一次清晰的用户确认，换取可预测的成本和版本关系。首版不提供多人自动合并内容分支；所有复用依据都可在界面解释。
