# G05｜需求、剧本与分镜 Agent

> 状态：DRAFT_FOR_REVIEW。交付阶段：B2。前置：G01–G04、G06 引用接口、G09 预算基础。交互：G07、G08、G14。

## 1. 目标与边界

把自然语言需求转成可修改、可校验的需求书、剧本和镜头说明。Agent 可以提出内容和调整建议；最终版本保存、审批和执行由领域服务管理。首版采用有明确输入输出的创作阶段，不要求多个 Agent 自由讨论。

## 2. 功能清单

| ID | 功能 | 输入与输出 | 交互对象 | 实现要点 |
|---|---|---|---|---|
| G05-F01 | 需求整理 | 用户文本/ProductProfile → CreativeBrief 草稿 | G03、G14 | 提取主题、受众、用途、风格和约束；标注缺失信息 |
| G05-F02 | 剧本生成与改写 | 已选 Brief + 修改意见 → ScriptRevision 草稿 | G03、G07 | 保留旁白段落 ID，分别存画面说明和朗读文本 |
| G05-F03 | 分镜规划 | 剧本 + 语音时长 + 参考素材 → Storyboard/Shot 草稿 | G06、G07 | 依据实际时间线安排镜头，写明动作、景别和衔接要求 |
| G05-F04 | 一致性与可执行性检查 | 草稿 → 检查报告/有限修订 | G07、G08 | 程序检查硬约束；模型辅助检查叙事与角色描述 |
| G05-F05 | 可替换执行适配 | CreativeTaskSpec → CreativeResult | G01、G04 | 结构化 LLM/Harness 使用同一合同；记录调用血缘 |
| G05-F06 | 可解释的修改建议 | 用户反馈 + 原版本 → ProposedChange | G12、G14 | 返回修改字段与原因，不自行覆盖当前头或批准 |

## 3. 输入输出合同

`CreativeTaskSpec` 包含 task_id、stage、input_refs、product_profile_ref、prompt_template_digest、provider_profile_ref、max_calls、token_limit、budget_reservation_id、operation_id。读取输入时验证引用摘要和访问权限。模型凭据不进入任务载荷。

`CreativeResult` 包含 output_schema_version、draft_payload、input_refs、validation_report、provider_call_refs、usage_actual、warnings。所有输出先通过 Schema 再落库；模型返回的 revision、审批状态、租户身份和执行命令均不可信，由服务端生成或拒绝。

`ProposedChange` 为明确的目标版本和字段更改列表，带 rationale、affected_entities_hint。影响范围提示只是建议，真正失效计算由 G12 按依赖图执行。

## 4. 创作流程与模块交互

1. G03 创建 CreativeTask，G04 调用 Provider；G09 预留本次预算。
2. 需求整理产出 Brief 草稿，UI 展示可编辑字段；信息缺失以 issue 表示，不无限发起追问循环。
3. 用户确认需求后生成剧本，按 narration_segment_id 保存朗读文本；不让模型声称估算时长等于实测时长。
4. G07 生成试配音及分段时间，G05 使用该结果生成或调整分镜。用户改剧本时创建新版本，再由 G12 判断配音/分镜是否需更新。
5. 程序检查镜头数、必填字段、引用存在性和时间范围；模型辅助指出角色服装、地点或动作矛盾。
6. 通过检查的结果保存为草稿，G03 返回新版本，G14 展示差异。只有用户审批或明确配置的审批策略能够放行制作。

## 5. 如何实现

提示词模板与输出 Schema 单独版本化，角色/品牌约束作为明确输入引用，不从长会话摘要中猜测。Provider 适配器负责结构化输出能力探测；不支持原生结构化输出时进行 JSON 提取和验证，但不得把自由文本直接当成生产规格。

初始策略：每个创作任务最多 3 次模型调用，其中一次初始生成、最多两次格式/内容修复；每次都有独立 operation_id 和用量记录。模板不要求返回模型的隐藏推理过程，保存可读的修改理由和检查结果即可。

硬约束检查用确定性程序实现：画幅枚举、镜头数量、时间线长度、引用版本、字符长度、禁止负帧数。软检查由模型输出带位置的意见和置信描述；不得把主观评分当成概率或替代人工审片。

Agent 可用工具仅包含读取已授权素材元数据、提交草稿、提交修改建议等领域能力。不得获得任意 Shell、ComfyUI 节点编辑、预算修改、审批写入和最终发布权限。Harness 适配器中的工具调用仍通过同样的服务端策略验证。

LLM 输出存入结果仓储后再返回 Activity；网络回报丢失先按 operation_id 查仓储/供应商回执。供应商不支持查询或去重且无法确认结果时，记录 OUTCOME_UNKNOWN，由用户选择重试并接受潜在重复调用成本；不能宣传绝无重复计费。

## 6. 失败处理

| 失败 | 处理 |
|---|---|
| Schema 不合法 | 保存诊断，进入有限修复；预算/次数耗尽则显示可编辑草稿与错误 |
| 需求互相冲突 | 返回字段级 issue，让用户修改；不静默删除约束 |
| 引用素材已失效/无权限 | 拒绝该任务，说明可公开的缺失项 |
| 生成途中用户编辑了基准版本 | 结果保存为候选旧分支，不能覆盖当前头；展示可比较内容 |
| Provider 超时或断线 | 分类为已知未提交/结果未知；按 G04 规则决定是否安全重试 |
| 达到预算上限 | 停在当前草稿，释放未使用预留，不再自行调用其他模型 |

## 7. 实现任务

实现 Provider 假对象与固定 Schema 样例 → Brief/Script/Storyboard 三阶段模板 → 程序校验器 → 修复次数和成本控制 → 草稿差异展示 → 真实 LLM 集成 → 可选 Harness 适配兼容测试。提示词编译成特定视频模型输入属于 G08，不放进本模块的自由工具循环。

## 8. 验收条件

- G05-A1：固定需求生成三种合法草稿；缺失字段可编辑，审批后才能进入制作。
- G05-A2：模型返回非法 JSON、越权字段或虚构素材引用时，不产生可执行 RenderJob。
- G05-A3：连续无效输出最多调用 3 次；预算不足时更早停止，保留用量和错误。
- G05-A4：创作任务运行中用户改版本，晚到结果不能覆盖用户修改。
- G05-A5：Provider 切换不改变上游项目和下游 ShotSpec 合同；调用和模板版本可追踪。
- G05-A6：同一任务恢复优先复用已保存结果；未知供应商调用不会无提示地无限重试。

## 9. 供审核的取舍

先追求稳定草稿和可解释修改，不承诺同一问题每次生成完全相同文本。已经批准的内容通过版本保存保持稳定；需要重复使用时读取该版本。是否加入更复杂 Agent 内部图，由具体创作质量和工具需求决定。
