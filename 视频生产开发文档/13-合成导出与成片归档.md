# G13｜合成、导出与成片归档

> 状态：DRAFT_FOR_REVIEW。交付阶段：B2 分镜预览媒体端口，B3 完整合成。前置：G02–G04、G06、G07、G09、G11；G12 提供局部重做输入。

## 1. 目标与边界

将已选镜头、配音、音乐和字幕按冻结时间线生成成片，并保存可再次下载的交付原件。输入固定、参数和工具版本可追踪；是否能逐字节重编码一致需单独验证，不把 FFmpeg 的可编程控制等同于所有编码环境必然一致。

## 2. 功能清单

| ID | 功能 | 输入与输出 | 交互对象 | 实现要点 |
|---|---|---|---|---|
| G13-F01 | 冻结合成输入 | Selection/Timeline/Audio/Subtitle → CompositionRevision | G02、G03、G11 | 只引用 READY 且兼容的具体 Artifact，固定输出 profile |
| G13-F02 | 媒体预处理 | 原生片段 → 统一可合成片段 | G07、G08、G06 | 明确尺寸、fps、色彩和裁切；派生结果登记血缘 |
| G13-F03 | 音视频合成 | CompositionSpec → 成片候选 | G04、G09、G11 | FFmpeg 参数化执行、受限目录、进度与有界终止 |
| G13-F04 | 字幕与混音 | 字幕/音轨 → 烧录字幕、独立 SRT、最终音轨 | G07、G14 | 字体锁定、响度 profile、旁白完整性检查 |
| G13-F05 | 成片确认与导出 | FinalApproval → ExportRecord/下载 | G03、G11、G14 | 绑定实际文件及版本，下载可重试，导出不等于对外发布 |
| G13-F06 | 归档和再合成 | 历史 CompositionRevision → 原件复用/新合成 | G06、G12、G16 | 保留输入清单、工具版本、文件摘要和审批 |

## 3. CompositionSpec 合同

包含 composition_id/revision、selection_ref、timeline_ref、每片段 artifact_ref 和 source_in_frame/source_duration、转场配置、音轨 AssetRef 和采样定位、字幕内容/样式引用、字体资源摘要、output_profile、ffmpeg_build_digest、处理模板版本、总帧数和内容摘要。

`MediaJob` 使用 media_job_id、operation_id、composition_digest、kind(animatic/normalize/compose)、status、attempt、owner、lease_fence、output_refs、日志引用。它遵守 G09 的预算/领取和 G04 的恢复原则；本地同 operation_id 先查已有合格输出，不能重入启动多个合成进程。

MediaPort 定义 submit(specRef, operationId)、query(operationId)、cancel(operationId)、collect(operationId)。G07 分镜预览调用同一端口的 animatic 模板，先以静态图片构造片段，不依赖真实 RenderJob 才能测试。

## 4. 实现流程

1. 冻结前验证选片完整、技术 QC 有效、时间线与字幕/音轨兼容；所有引用和摘要进入 CompositionRevision。
2. Worker 领取 MediaJob，在受控目录下载输入并再次校验摘要；空间不足返回资源错误，不开始部分输出。
3. 探测每个片段的尺寸、fps、时间基、音轨及色彩标签；按 G07 时间线解释源片段裁切点。
4. 使用固定模板生成滤镜图和参数数组，执行 normalize/concat/transition/audio/subtitle；标准输出只用于进度，stderr 有限量脱敏保存。
5. 输出到临时文件，完整解码与探测通过后交给 G06 登记；上传失败只重试收集，不重复合成。
6. G11 进行最终技术检查与人工审片；批准具体 Artifact 后 G13 事务创建 ExportRecord，G04 完成本次制作。

## 5. 音视频处理规则

默认输出 profile：720×1280、24/1 fps、H.264/yuv420p、SDR BT.709；AAC、48 kHz、双声道。源素材缺少色彩信息时采用经过审核的默认解释并记录警告；HDR 输入首版拒绝或走独立经过测试的转换模板，不能错误标记为 SDR。

画幅不匹配默认等比缩放加边框，避免静默裁掉主体；裁切和主体重构需要明确的 crop/layout 配置。原生时长不足时拒绝或采用已确认的静帧/补片方案，不通过无提示加速/减速满足总时长。fps 标准化按时间戳重采样，不等同于 AI 插帧；AI 插帧属于独立有来源的派生产物。

时间线用整数帧计算。需要重编码统一规格时走受控滤镜模板；不能直接拼接任意编码、fps、时间基的 MP4 文件。片段 PTS 归零、转场重叠与音频定位必须按同一绝对时间基处理。

旁白不得截断。输出响度首版目标建议综合 -16 LUFS、true peak 不高于 -1 dBTP，写入 AudioOutputProfile；执行两遍测量/处理并记录实际值。该值是本产品的可修改默认值，不声称适用于所有发布平台。音轨短于画面时以明确静音补齐，长于画面则冻结前报冲突。

字幕用锁定字体和样式生成受控 ASS/字幕资源，处理文本转义与路径转义；不能把用户字幕直接拼进 Shell 命令。中文长句、标点、表情符号和缺字均需预览检查。另提供内容一致的 SRT 文件。

FFmpeg 提供缩放、拼接、响度与字幕等滤镜；实际可用能力取决于锁定制品的编译选项，应在 G01/G16 基线中验证。[FFmpeg 滤镜文档](https://ffmpeg.org/ffmpeg-filters.html)

## 6. 安全执行、恢复与导出

使用进程参数数组而非拼接 Shell；文件路径只来自 G06 已解析的受控本地映射。限制单任务临时空间、CPU 并发、日志大小和总运行时间。取消必须终止本任务拥有的进程树并验证停稳，不能按进程名杀所有 FFmpeg。

本地工作日志记录临时输出、最终输出摘要和上传状态。进程重启后若存在完整校验通过的结果则收集；只剩损坏临时文件时重新执行相同 MediaJob 的新尝试，保留旧失败证据。

ExportRecord 包含 composition_ref、final_artifact_id/digest、subtitle_ref、lineage_manifest_ref、approval_ref、output_profile、导出时间。下载授权到期可重新申请；重复下载不触发新合成。用户要求新画幅时创建新输出计划并评估构图，不声称简单缩放等同于重新设计竖屏。

## 7. 实现任务

固定素材实现 animatic → MediaPort/日志/资源限制 → normalize 模板 → 时间线合成 → 配音与字幕 → Artifact/QC 交互 → 成片批准与 ExportRecord → 重启/取消/上传失败测试。

## 8. 验收条件

- G13-A1：固定示例完整解码，尺寸/编码/轨道符合 profile，720 帧目标偏差不超过一帧；旁白没有丢字/截断。
- G13-A2：不同原生 fps/尺寸的片段按计划统一；未经确认的裁切、变速、HDR 转换被拒。
- G13-A3：中文字幕不越界，指定字符样例无缺字；SRT 时间与烧录字幕对应。
- G13-A4：合成完成后上传中断，恢复不增加 FFmpeg 执行次数；损坏中间文件不会被登记 READY。
- G13-A5：取消仅影响目标进程树；恶意字幕/路径无法执行额外命令。
- G13-A6：重复下载返回同摘要原件；修改字幕只创建新合成版本，不重复生成镜头。
- G13-A7：成片未批准不能登记为已交付 ExportRecord；预览下载可用但明确标为草稿。

## 9. 供审核的取舍

首版提供固定规格和有限转场，优先保证语音、字幕、画面和版本一致。导出是生成下载交付物，社交平台发布属于独立后续功能。选中原件和合成输入必须保存，以支持后续修改。
