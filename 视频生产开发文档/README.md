## 如何审核

本目录把最终目标拆成 G00–G17 共 18 个目标，每个目标单独一个文件。每份文件均包含：目标与边界、功能清单、模块交互、数据或接口、实现步骤、失败处理、验收场景和审核取舍。表格中的功能 ID 可直接用于提出修改意见，例如“G10-F03 的未知结果处理需要调整”。

本版共列出 107 项功能、111 项目标验收条件，另在 G17 汇总 16 个跨模块故障场景。已进行文档结构、功能 ID 引用和本地链接检查；这不代表这些软件功能已经实现或验收通过。

先读 G00 的产品范围、G01 的系统关系和 G02 的数据模型，再按目录阅读。G17 汇总开发顺序及整体验收；编号是阅读顺序，实际实现按依赖和阶段推进。所有功能当前均为设计状态，表中的实现路径是建议创建的位置，不表示代码已存在。

本目录针对新的视频生产能力。原稿引用的 `../UI开发/` 是 Harness 桌面客户端合同，`../开发文档/` 是 Runtime 学习与复刻课程；这些目录和对应桌面工程未包含在当前仓库中。后续接入时再核对实际合同。接入所需的桌面扩展列在 G01、G14，独立桌面实现也须满足相同业务边界。[当前技术选型](../技术选型与ComfyUI对接方案.md)

## 本方案修正了什么

| 原方案中的不足 | 本次明确的处理 | 责任目标 |
|---|---|---|
| 桌面退出和后台继续生产的生命周期冲突 | 视频服务独立托管；桌面自有 Harness 仍按旧规则退出 | G01、G14、G16 |
| 数据库与 Temporal 都可能修改流程状态 | 领域模块是业务写入入口；Temporal 安排执行，业务状态由领域事务写入 | G02、G03、G04 |
| 认为一个幂等键就能避免重复 GPU 执行 | 请求、逻辑任务、执行尝试分层；提交结果不明先回查，无法消歧则暂停 | G09、G10 |
| 相同参数去重会阻止用户主动再生成 | 重试复用任务身份；新候选使用新的任务身份 | G03、G09、G12 |
| 版本号无法决定局部重做范围 | 显式依赖边和实际输入摘要，支持跨制作批次复用 | G02、G12 |

## 共同约定

- `Gxx-Fnn` 是功能 ID，`Gxx-An` 是验收 ID；ID 不复用。文件中的功能表为功能清单真源。
- “必须”表示该目标对应交付阶段的完成条件；“后续”表示明确不计入首版完成声明的范围。
- `revision` 是不可变内容版本；`row_version` 是数据库并发控制序号；两者不能互换。
- 幂等：重复同一操作不会产生额外业务效果。它不自动等于外部服务只运行一次。
- Outbox：与业务数据在同一数据库事务中保存的待发送事件，解决“写成功但通知丢失”。
- Worker：执行任务的后台程序；租约：限定时间内的领取资格；fence：领取世代号，用于拒绝旧执行者写入。
- 血缘：产物引用的需求、模型、工作流、素材、参数和环境来源。
- 所有租户 ID 从认证上下文取得；下文省略认证参数的接口仍必须执行 G15 的授权。
- 大文件进入素材存储；队列、Temporal 历史和 API 只传引用及小型元数据。
- 本地文件开发后端和 S3 兼容生产后端必须满足同一 StoragePort 合同，不依赖某个存储品牌特性。
