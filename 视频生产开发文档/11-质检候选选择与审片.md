# G11｜质检、候选选择与审片

> 状态：DRAFT_FOR_REVIEW。交付阶段：B3。前置：G02、G03、G06、G07、G10。下游：G12–G14；扩展质量评估由 G17 验证。

## 1. 目标与边界

将“文件技术可用”和“画面符合创作要求”分别检查，帮助用户选择候选并冻结选片结果。首版技术检查自动执行，创作质量以人工审片为准；视觉模型可提出意见，未经校准不能自动批准或无限重做。

## 2. 功能清单

| ID | 功能 | 输入与输出 | 交互对象 | 实现要点 |
|---|---|---|---|---|
| G11-F01 | 技术质检 | Artifact + 预期 profile → QCReport | G10、G13 | 解码、时间/帧数/分辨率、必需音轨、异常帧诊断 |
| G11-F02 | 候选组织与比较 | 同镜头结果 → CandidateView | G14、G06 | 保留来源、成本、执行与内容版本，支持并排播放 |
| G11-F03 | 人工审片与选中 | artifact_id + 决定 → Review/SelectionRevision | G03、G12、G13 | 绑定实际文件摘要，选中对象不可被晚结果替换 |
| G11-F04 | 拒绝与修改反馈 | 问题描述 → ChangeRequest | G05、G12 | 区分再生成候选、改内容、改后处理，不直接重提旧任务 |
| G11-F05 | 语义辅助质检 | 视频/分镜 → 建议性报告 | G05、G17 | 标注评估器版本、抽样方法和局限；默认不自动放行 |
| G11-F06 | 成片审批 | Composition Artifact → FinalApproval | G03、G13、G14 | 最终审核绑定具体合成版本及文件，不继承低清预览批准 |

## 3. 质检合同

`QCReport` 包含 qc_id、artifact_id/digest、rule_profile_version、probe_version、checks、overall_technical_status、warnings、created_at。每条 check 有 code、expected、observed、severity、evidence_ref，不能只返回一个无法解释的分数。

技术硬失败：文件不能完整解码、必要轨道缺失、尺寸/长度不满足对应阶段合同、帧时间倒退、输出损坏。黑帧、静帧、画面闪烁默认作为诊断警告，因为黑场和静止画面可能是创作意图；只有具体镜头合同明确禁止且检测规则经过验证时才升级阻断。

渲染原件按 G08 原生 profile 检查；最终交付按 G00/G13 输出 profile 检查。不能用最终 720×1280/24fps 的要求直接拒绝合法的原生中间素材。

## 4. 选片与审批交互

1. G10 登记 READY Artifact，G04 安排技术 QC；成功/失败报告持久化并向 G14 发业务事件。
2. UI 按 shot_ref 和 candidate_id 显示候选、问题、来源及耗时，区分旧版本/当前版本候选。
3. 用户选择具体 artifact_id，提交 `SelectCandidateCommand(command_id, slot_id, artifact_ref, expected_selection_version)`。
4. 服务端验证 READY、技术可用、访问权限和镜头依赖兼容；事务追加 SelectionRevision/Review 与依赖边。
5. 全部必需槽选定后，G13 可以冻结 CompositionRevision；缺失或过期槽阻止合成并列出具体原因。

选择历史候选时必须验证其 RenderSpec 实际输入能满足当前镜头/参考素材要求；用户希望保留不兼容旧镜头时，需要通过 G12 明确调整内容/依赖，不能在选片接口里静默忽略冲突。

Review 记录 reviewer_id、decision、artifact_digest、shot_revision、notes、时间和 policy_version。任何高分新候选都不会自动覆盖用户已选片段。

## 5. 预览、后处理和重新生成

分镜预览批准只说明节奏和构图方案已确认。生成视频候选批准绑定实际视频原件。放大、插帧、重编码或重新生成都产生新 Artifact；新结果至少重新技术检查，内容改变的派生结果需要人工确认。

用户选择“再生成一个”走 G12 新候选路径；选择“改动作/换人物”创建内容新版本并计算依赖；选择“裁掉末尾”修改时间线/后处理计划。按钮必须与不同业务动作一一对应。

## 6. 辅助视觉评估实现

后续增加评估器时，先建立经人工标注的样例集合，覆盖人物、动作、闪烁和镜头衔接。评估器读取受控低分辨率抽帧或视频输入，输出问题位置、描述、证据帧和评分定义。

不得将任意 0–1 分数直接称为准确率或置信概率。记录漏检/误报与人工一致率，用独立验证集确定是否适合自动阻断。动作缺陷可能发生在未抽样帧中，报告应注明抽样密度和覆盖限制。

Alpha 语义评估可以不启用；技术 QC 与人工审片必须存在。启用后调用成本纳入 G09，失败降级到人工审片，不阻塞已可人工判断的候选。

## 7. 失败与实现任务

技术检测工具崩溃时报告 CHECK_FAILED，与媒体不合格区分；可重试检测，不能重试生成来代替检测。人工拒绝不是基础设施失败。用户同时选片时按 SelectionRevision 并发控制返回冲突。

实现任务：探测/完整解码 → QCReport/规则版本 → 候选列表与比较 DTO → 选片领域命令 → 成片审批 → 可选视觉评估端口。所有具体 UI 在 G14 实现。

## 8. 验收条件

- G11-A1：损坏视频、异常时间戳、缺必需音轨被拒；合同允许无音轨或黑场时不误判硬失败。
- G11-A2：用户选中 A 后 B 晚到，即使 B 评分更高，SelectionRevision 仍引用 A。
- G11-A3：并发选片只允许基于当前版本的合法写入；错误槽、跨租户或不兼容旧候选被拒。
- G11-A4：低清/静态预览批准不能替代新生成结果或最终成片审批。
- G11-A5：语义评估服务不可用时仍能人工审片；质量拒绝不会触发无上限自动生成。
- G11-A6：每次选片和成片批准可追溯到具体 artifact_digest、内容版本和审核人。

## 9. 供审核的取舍

首版默认人工决定创作质量，自动检查专注可验证的技术问题。将评分系统作为后续可评估能力，避免先堆复杂评估服务却无法判断分数是否有用。
