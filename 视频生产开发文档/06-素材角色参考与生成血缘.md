# G06｜素材、角色参考与生成血缘

> 状态：DRAFT_FOR_REVIEW。交付阶段：B1 上传/存储基础，B2 真实生成素材。前置：G01–G03、G15 身份基础。交互：G05、G07–G14、G16。

## 1. 目标与边界

可靠保存参考图、音频、原始生成视频、选中镜头和成片。用户能知道某个结果使用了哪些内容版本、模型和输入文件。素材库不承诺通过几张参考图即可保证任意视频模型的人物一致性，实际支持能力由 G08 的工作流包声明并验收。

## 3. 数据与端口

`StoragePort` 提供 beginUpload、putPart/streamUpload、completeUpload、head、openRead(range)、deleteObject。供应商 Multipart 的 ETag 不能直接当成文件 SHA-256；应用计算并记录统一摘要。

业务 `AssetRef` 使用 asset_id、revision；生成 `ArtifactRef` 使用 artifact_id。ArtifactManifest 关联其文件 AssetRef，附执行来源和探测结果。领域对象不保存用户机器绝对路径、临时下载 URL 或 ComfyUI output 路径。

`ReferenceSetRevision` 包含 reference_set_id、revision、角色/场景描述、图片角色标签、AssetRef、用户选定记录及适用限制。替换某张图创建新版本；G12 据此更新依赖镜头。生成参考图也是受预算约束的生成任务，不能在上传接口里偷偷触发模型。

外部接口：POST `/assets/uploads` 申请票据；POST `/assets/uploads/:id/complete` 确认上传；GET `/assets/:id` 查元数据；GET `/artifacts/:id/lineage` 查来源；DELETE `/assets/:id` 提交删除命令。都通过 G03/G15 的幂等和权限规则。

## 4. 上传及产物发布实现

1. 事务创建 UploadRecord 和 UPLOADING Asset，保存允许大小、类型、所有者与过期时间。
2. 文件流写入隔离的 staging 对象，限制字节数、并发和总空间；不能先把整个视频读入 API 内存。
3. 服务端校验真实媒体类型、解码能力、SHA-256、大小和必要元数据；失败标 QUARANTINED，不能选用。
4. 将已验证字节放到不可覆盖的最终对象键，或把当前版本固定为只读。读取确认成功后，事务更新 Asset.READY、写 Manifest/依赖边、业务事件与 Outbox。
5. 成功回报丢失时，按 upload_id/artifact_identity 查询原记录；不要再生成视频或创建重复的逻辑 Artifact。

对象存储和 PostgreSQL 无跨系统原子事务。文件成功而数据库失败时，保留上传记录与对象标签供回收/补登记；数据库不能先发布 READY 再假设文件迟早会出现。回收器仅删除超过宽限期且没有有效引用的 staging/orphan 对象。

Render Worker 通过局部工作目录收集文件；目录路径必须规范化并确认处于本次执行允许的根内。禁止采信节点输出的任意绝对路径或 `../` 路径。原始文件完成上传后才能清理本地目录；剩余空间不足时停止接单。

## 5. 血缘内容与复现边界

每个生成 ArtifactManifest 至少包含：输入 Asset/Artifact 摘要、内容与 RenderSpec 引用、实际提示词、具体种子、模型/LoRA/VAE 摘要、工作流图及绑定摘要、自定义节点版本、Worker 环境与框架/驱动版本、编译器版本、执行任务/尝试 ID、输出摘要、创建时间和媒体探测结果。LLM/TTS 来源同样记录供应商、请求参数和可用的模型版本信息，缺失信息标为未提供，不伪造精确模型哈希。

定义三个可独立验证的能力：

- 原件复用：按已保存摘要读取同一文件，这是交付保存的基础保证。
- 过程追溯：能解释产物的输入和执行来源，包括已知信息缺口。
- 条件重算：在限定依赖、硬件/算法配置下验证重算效果；不默认承诺跨环境逐字节相同。

固定随机种子不足以保证跨平台、版本或算法完全一致，重算报告要注明环境和比较方法。[PyTorch 可复现性说明](https://docs.pytorch.org/docs/2.9/notes/randomness.html)

## 6. 删除、缓存与安全

对象键按租户命名空间隔离；首版不做跨租户内容去重，避免摘要探测泄露他人文件是否存在。同租户去重只复用字节存储，不合并操作身份、审批记录或候选记录。

DELETE 先标记 DELETE_PENDING，并列出被引用的快照/选片/成片。活跃制作、用户保留版本和有效备份持有保留引用；有引用时拒绝物理删除或要求明确删除整个相关项目，不能默默让旧项目损坏。实际删除采用标记、宽限期、二次引用检查、物理清理、审计五步。

默认上传票据有效 1 小时，未完成上传 24 小时后可回收；已选片段和成片不自动删除，非选中候选默认保留 30 天再按项目策略处理。所有期限是版本化配置；空间超限时停止新写入并提示，不优先删用户选中结果。

## 7. 实现任务

建立两种 StoragePort 适配及同一合同测试 → 上传确认与媒体探测 → Manifest/依赖边 → 参考集合编辑 → Range 读取/缩略图 → 保留引用与 GC → 故障恢复演练。首版需要完成上传和存储基础，自动生成多角度角色图可以后续扩展。

## 8. 验收条件

- G06-A1：上传中断/重复确认不产生可用半文件；校验失败文件不能进入 RenderSpec。
- G06-A2：对象写成功但数据库失败，恢复后可补登记或安全回收，无永久 READY 空引用。
- G06-A3：已选 Artifact 的字节摘要保持不变；可以沿引用查到对应输入、工作流和尝试。
- G06-A4：删除被活跃快照引用的素材被阻止；非引用孤立文件宽限期后被回收。
- G06-A5：跨租户读取、过期票据、伪造文件类型和目录逃逸请求均失败。
- G06-A6：同一存储合同在开发文件后端和选定生产对象存储通过，包含 Range、校验与中断恢复。

## 9. 供审核的取舍

首版以保存原始结果和可靠血缘为基础，默认保留用户选中的素材。多角度参考图提供创作帮助，其效果必须在所选模型上验证，不把素材管理系统描述成角色一致性的自动保证。
