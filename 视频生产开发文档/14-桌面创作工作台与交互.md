# G14｜桌面创作工作台与交互

> 状态：DRAFT_FOR_REVIEW。交付阶段：B3；B1/B2 使用开发验收界面。前置：G01–G03、G15 身份基础，各页面对接 G05–G13。现有桌面基线：Electron + React。

## 1. 目标与边界

用户可以在现有桌面应用内完成视频创作。界面展示业务版本和真实任务状态，编辑草稿、确认输入、审片和重新生成都有明确反馈。视频功能作为新的领域工作台接入，不把视频项目伪装成 Harness 对话 Session，也不让 Renderer 直接访问 ComfyUI、数据库或 Temporal。

## 4. 前后端状态交互

Video Bridge 提供 getProjectSnapshot、subscribeProjectEvents、executeVideoCommand、queryCommand、uploadAsset、readMediaRange 等窄接口。请求/返回都通过运行时 Schema 校验。command_id 在用户一次意图开始时生成，重试/查询复用；新意图新 ID。

React 领域状态从版本化快照和事件派生，Zustand 只保留选中标签页、面板开关、播放位置等 UI 状态。未保存草稿与服务器 revision 显式分开，不能靠乐观更新把审批/任务状态提前标成功。

断线先展示离线及最后同步时间。重连按 G03 event_cursor 补事件；缺口或过期则重新加载快照并重放本地未提交草稿的差异提示。重启后的 command_id 结果未确认时先查询，不把按钮重按当成新生成。

## 5. 媒体通道与文件边界

Renderer 使用不透明媒体句柄，例如应用自定义媒体协议的 asset handle；不接收对象存储凭据、完整签名 URL、真实路径或 ComfyUI 地址。Main 的受控媒体协议处理器验证窗口身份/句柄权限，经 Video Bridge 请求字节范围并以有界流返回播放器。

该通道支持 Range、seek、取消读取、句柄过期重建和最大并发流；不会把整段视频通过一条 IPC 消息传输。必要缓存按 G06 保留规则设置大小与回收，缩略图和原视频分开加载。URI 解析拒绝路径拼接和任意 URL 转发。

文件导入通过现有受控文件选择能力获得上传句柄；后台按句柄读取允许的文件流。下载通过明确的保存对话框或用户配置位置完成，不能让 Agent 选择任意系统路径。所有网络由受控 Bridge/服务端承担，Renderer CSP 继续禁止任意网络连接。

具体自定义媒体协议、流背压及 Electron 版本支持在 G01 原型中验证后冻结；若验证不通过，先采用有容量上限的本地受控缓存读取，不绕过安全边界直接暴露远程凭据。

## 6. 必须区分的 UI 状态

- “正在排队”没有 GPU 进度，显示等待和原因；没有可靠估计时不显示虚构完成百分比。
- “正在生成”和“正在上传结果”是不同阶段，上传失败不能显示为重新生成。
- OUTCOME_UNKNOWN 显示“提交结果待确认”，提供回查证据/请求处理，不提供默认自动重试。
- PAUSED 说明不会开始新工作，在途任务可能继续；CANCEL_REQUESTED 显示等待停止确认。
- “分镜预览”是静态节奏预览；“镜头候选”“后处理候选”“成片草稿”分别标识。
- 两个用户或页面发生版本冲突时保留本地输入，让用户比较后重新保存，不能清空草稿或后台覆盖。

## 8. 实现任务与验收

实现顺序：Video Client/模拟服务 → 项目/编辑/审批页 → 上传与音频/静态预览 → 任务面板 → 候选选片与影响页 → 成片播放器/下载 → 重连与权限测试。

- G14-A1：用户无需理解节点编号即可完成固定 8 步制作流程；主要按钮均有对应命令结果。
- G14-A2：断线重连、重复点击和响应丢失不会额外生成；未确认命令先查询原结果。
- G14-A3：用户在编辑中收到旧 Agent 结果或旧候选，不丢失草稿、不覆盖选片。
- G14-A4：媒体播放支持 seek 和取消，内存随缓冲上限稳定，不随整段视频大小无界增长。
- G14-A5：Renderer 无服务秘密/真实路径/任意 URL 读取能力；越权媒体句柄失败。
- G14-A6：键盘可完成审批、选择、取消；状态文字可读，动画关闭后所有业务反馈仍存在。
- G14-A7：关闭桌面只断开客户端，重新打开能恢复项目和后台执行状态。

## 9. 供审核的取舍

首版提供分镜槽时间线和候选墙，不实现自由拖拽的专业非线性剪辑器。用户界面以创作对象和动作表达；模型哈希、租约 fence 等调试信息只放在诊断详情，不要求普通用户理解才能操作。
